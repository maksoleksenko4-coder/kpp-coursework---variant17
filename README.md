# Клієнт-серверна система моніторингу сільськогосподарських полів та обліку проблем (Варіант №17)

## Призначення програми
Інформаційна система призначена для обліку сільськогосподарських полів, фіксації результатів польових спостережень, реєстрації виявлених проблем та планування заходів обробки. Ключовими сутностями предметної області є **поля** (`field`), **спостереження** (`observation`), **проблеми** (`problem`) та **заходи обробки** (`treatment_action`). Через графічний клієнт JavaFX користувач може переглядати таблиці, виконувати CRUD-операції, перевіряти автоматичний розрахунок інтегрального показника ризику та правила переходів життєвого циклу проблеми, а також виконувати фоновий імпорт спостережень із CSV-файлу.

## Технології
* **Java 21** — основна мова розробки серверної та клієнтської частин.
* **Maven** — збірка модулів `server` і `client`, керування залежностями та запуск тестів.
* **JavaFX 21** — побудова графічного інтерфейсу користувача (GUI) та фонових задач (`Task`).
* **Java Servlet API 4.0.1** та **Apache Tomcat 9.x** — веб-контейнер, що запускає зібраний WAR-архів та обробляє HTTP/JSON-запити.
* **MySQL** та **JDBC (`mysql-connector-j 9.7.0`)** — реляційна база даних для зберігання даних і доступ до неї з серверного DAO-рівня.
* **Jackson (`jackson-databind 2.18.2`)** — серіалізація та десеріалізація JSON.
* **JUnit 5 (`junit-jupiter 5.11.4`)** — автоматизоване модульне тестування серверної логіки.
* **Git** — контроль версій.

## Підготовка бази даних
1. Встановіть і запустіть локальний сервер **MySQL** (наприклад, через XAMPP) та переконайтеся, що служба доступна.
2. Виконайте кореневий файл `database.sql` через інструмент імпорту **phpMyAdmin** або SQL-клієнт.
3. Перевірте, що створено базу даних **`field_monitoring`** та 4 основні таблиці: `field`, `observation`, `problem`, `treatment_action`.
4. За потреби налаштуйте локальні параметри підключення (`URL`, `USER`, `PASSWORD`) у класі `DBUtil` серверного модуля (справжні паролі та секрети в репозиторії не зберігаються).

## Запуск сервера
Команди Maven для серверної частини виконуються з каталогу `server/`:
```powershell
cd server
mvn clean test
mvn clean package
```
1. Скопіюйте зібраний архів `server/target/server.war` у папку `webapps/` сервера **Apache Tomcat 9.x**.
2. Запустіть Tomcat (`catalina.bat run`) і переконайтеся, що розгортання пройшло без помилок.
3. Перевірте роботу REST API у браузері (має повернутися коректний JSON):
    * `http://localhost:8080/server/fields`
    * `http://localhost:8080/server/observations`
    * `http://localhost:8080/server/problems`
    * `http://localhost:8080/server/actions`

## Запуск JavaFX-клієнта
Перед запуском клієнта обов’язково мають працювати **MySQL**, **Apache Tomcat 9.x** та перевірені GET-маршрути сервера (клієнт не працює автономно без сервера і не має прямого доступу до MySQL).

З кореня репозиторію виконайте:
```powershell
cd client
mvn javafx:run
```
* Клієнт звертається до сервера за адресою `BASE_URL` (`http://localhost:8080/server`). У разі помилки підключення або HTTP 404 перевірте контекст `server.war` і стан Tomcat.
* Відносний шлях `sample-data/observations.csv` рахується від робочого каталогу `client/`, тому запускати клієнт потрібно саме з папки `client/`.

## Тестування
Модульні тести JUnit 5 розміщені у `server/src/test/java` і запускаються незалежно від MySQL, Tomcat та JavaFX:
```powershell
cd server
mvn clean test
```
Очікувано: **10 тестів, 0 помилок (`BUILD SUCCESS`)**. Перевіряються:
* розрахунок інтегрального показника ризику в `RiskCalculator` (межі `0` та `100`, демонстраційні й CSV-дані);
* валідація діапазону факторів `0..100` (відхилення значень `< 0` та `> 100` через `IllegalArgumentException`);
* правила переходів життєвого циклу проблеми в `ProblemService` (дозволені `DETECTED → CONFIRMED → TREATMENT_PLANNED → RESOLVED` та заборонений `DETECTED → RESOLVED`).

## CSV (фоновий імпорт)
Імпорт спостережень із CSV-файлу (`client/sample-data/observations.csv`):
* **Формат:** `field_id;date;description;f1_score;f2_score;f3_score` (6 полів)
* **Кодування:** UTF-8
* **Роздільник:** `;` (крапка з комою)
* **Імпорт:** у вкладці «Спостереження» натиснути **«Імпортувати CSV»** — імпорт виконується у фоновому режимі (`ImportObservationsTask`) через HTTP POST (без прямого JDBC) із відображенням `ProgressBar`, статусом «Готово. Імпортовано: 3» та журналюванням у `Logger`.

> **Увага:** не потрібно імпортувати той самий CSV повторно, якщо його рядки вже є в MySQL — система не виконує автоматичної дедуплікації, що може створити дублікати.
